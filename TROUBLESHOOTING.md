# Устранение проблемы с /src/main.tsx

## Проблема
Ошибка: `GET https://equipoise7.github.io/src/main.tsx net::ERR_ABORTED 404`

Эта ошибка означает, что браузер пытается загрузить исходный файл вместо собранного.

## Возможные причины и решения

### 1. На GitHub Pages еще не задеплоена новая версия

**Решение:**
1. Зайдите на GitHub в ваш репозиторий
2. Перейдите в **Actions**
3. Убедитесь, что последний workflow завершился успешно (зеленая галочка)
4. Если workflow еще выполняется, подождите его завершения (обычно 2-3 минуты)
5. Если workflow завершился с ошибкой, проверьте логи

### 2. Неправильный base path

**Проверка:**
1. Откройте ваш сайт в браузере
2. Посмотрите на URL в адресной строке:
   - Если URL: `https://equipoise7.github.io/` → base должен быть `/`
   - Если URL: `https://equipoise7.github.io/ossetian-peaks-tours/` → base должен быть `/ossetian-peaks-tours/`

**Решение:**
Откройте `vite.config.ts` и измените строку 78:

```typescript
// Для корня (username.github.io):
const basePath = process.env.VITE_BASE_PATH || '/';

// Для подпапки (username.github.io/repo-name/):
const basePath = process.env.VITE_BASE_PATH || '/ossetian-peaks-tours/';
```

Затем задеплойте изменения:
```bash
git add .
git commit -m "Fix base path"
git push
```

### 3. Кеш браузера

**Решение:**
1. Очистите кеш браузера:
   - Chrome/Edge: `Ctrl+Shift+Delete` (Windows) или `Cmd+Shift+Delete` (Mac)
   - Выберите "Изображения и файлы в кеше"
   - Нажмите "Удалить данные"
2. Или откройте сайт в режиме инкогнито
3. Или выполните жесткую перезагрузку:
   - `Ctrl+Shift+R` (Windows/Linux)
   - `Cmd+Shift+R` (Mac)

### 4. GitHub Pages использует старую версию

**Решение:**
1. Зайдите в **Settings** → **Pages**
2. Убедитесь, что источник установлен на **"GitHub Actions"**
3. Проверьте, что ветка правильная (main или master)
4. Попробуйте перезапустить workflow:
   - Зайдите в **Actions**
   - Найдите последний workflow
   - Нажмите "Re-run all jobs"

### 5. Проверка собранных файлов

**Локальная проверка:**
```bash
# Соберите проект локально
npm run build

# Проверьте, что в dist/index.html правильные пути
cat dist/index.html | grep -E "(src=|href=)"

# Должны быть пути вида:
# /assets/index-xxxxx.js
# /assets/index-xxxxx.css
# НЕ должно быть: /src/main.tsx
```

Если в `dist/index.html` есть `/src/main.tsx`, значит сборка прошла неправильно.

## Быстрая диагностика

1. **Проверьте URL сайта:**
   - Откройте сайт в браузере
   - Посмотрите на URL в адресной строке
   - Это покажет, в корне ли сайт или в подпапке

2. **Проверьте консоль браузера:**
   - Откройте консоль разработчика (F12)
   - Посмотрите на ошибки
   - Проверьте, какие пути пытается загрузить браузер

3. **Проверьте GitHub Actions:**
   - Убедитесь, что последний workflow завершился успешно
   - Проверьте время последнего деплоя

4. **Проверьте файлы на GitHub:**
   - Зайдите в репозиторий
   - Перейдите в Actions → последний workflow
   - Найдите артефакт "pages-artifact"
   - Проверьте, что там есть файлы `index.html` и `404.html`
   - Откройте `index.html` и убедитесь, что там правильные пути к ресурсам

## Если ничего не помогает

1. Убедитесь, что вы используете правильный base path (см. выше)
2. Убедитесь, что GitHub Actions успешно задеплоил проект
3. Очистите кеш браузера
4. Попробуйте открыть сайт в другом браузере или в режиме инкогнито
5. Проверьте, что в `vite.config.ts` base path установлен правильно
6. Пересоберите проект локально и проверьте `dist/index.html`
